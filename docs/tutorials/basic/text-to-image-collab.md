## 零、准备ComfyUI环境

### 1. 方法一：本地ComfyUI

先确认你已经安装好 ComfyUI，打开后能看到画布。如果还没有安装，可以先看 [ComfyUI 官方安装指南（站外）](https://docs.comfy.org/zh/installation/desktop/windows)；这是 Windows 桌面版的入口，其他系统和安装方式可在官方文档里选择。

把模型想成这条流水线用来画图的工具和经验。没有模型，光写一句提示词，电脑还不知道该怎么把它变成图。

本课使用的是一个 SD1.5 模型。
模型名称：`v1-5-pruned-emaonly-fp16.safetensors`
下载地址：[v1-5-pruned-emaonly-fp16.safetensors（站外）](https://huggingface.co/Comfy-Org/stable-diffusion-v1-5-archive/blob/main/v1-5-pruned-emaonly-fp16.safetensors)，文件约 **2.1 GB**。
存放路径：把模型放到 ComfyUI 模型目录的 `checkpoints` 文件夹里。常见位置是：
- **Windows 便携版**：`ComfyUI_windows_portable/ComfyUI/models/checkpoints/`
- **手动安装**：`ComfyUI/models/checkpoints/`
- **桌面版**：可以在 ComfyUI 的帮助菜单中找到打开模型文件夹的入口，再进入 `checkpoints`。

如果你改过模型路径，请使用自己的实际路径。放好后回到 ComfyUI，按 `R` 刷新；如果列表仍没更新，重启一次。

### Checkpoint加载器（简易）[Load Checkpoint]

这是第一个节点，负责把模型目录下的模型加载上来，也可以理解为后面要用那个模型，在这里配置好。本教程我们使用这个模型：`v1-5-pruned-emaonly-fp16.safetensors`。
配置好模型后，可以看到这个节点的右侧有三个圆圈，右侧的这三个圆圈表示节点的输出，也就是这个模型里面有三个东西，可以给后面的节点用，分别是：
- `MODEL`：模型本体，真正跑的就是这玩意，用来生成图像的。
- `CLIP`：后面用来处理文字要求。
- `VAE`：后面用来把生成过程中的数据转换成可查看的图像。

稍后我们会分别把它们接出去。现在选好模型就可以，先不要急着运行。

如果下拉框里找不到模型，优先检查：文件是否下载完整、是否放进正确的 `checkpoints` 文件夹、放好后是否刷新或重启。

### 第二步：Empty Latent Image —— 先确定画布规格

添加 **Empty Latent Image**，把参数设置为：

- `width`：`512`
- `height`：`512`
- `batch_size`：`1`

**一句话理解：它先给后面的生成过程准备一份指定大小的空白数据。** 可以暂时把它想成画画之前选纸张规格：512 × 512 是正方形，`batch_size` 是这次准备生成多少张。

它并不是一张普通的白色图片；这个比喻只是帮助我们先理解它的作用。这里使用 512 × 512，是为了跟本课的 SD1.5 示例对齐。尺寸变大通常更占显存，也会改变画面构图。

有些版本新建节点的默认尺寸不是 512，所以记得自己检查一遍。

### 第三步：两个 CLIP Text Encode —— 把要求说清楚

搜索 **CLIP Text Encode (Prompt)**，添加 **两个**。名字和外观一样，但我们分配给它们不同的工作：一个写正向要求，一个写负向要求。

**一句话理解：它把我们写的文字要求处理成后面生成节点能使用的条件。**

在第一个节点里填写正向提示词，也就是“想要什么”：

```text
beautiful scenery nature glass bottle landscape, , purple galaxy bottle,
```

大意是：自然风景、玻璃瓶，以及装着紫色星河的瓶子。这里保留示例原文，包括其中连续的逗号，是为了尽量和开头的参考效果对齐。提示词不是咒语，后面我们会亲手改一处，看看画面怎么变化。

在第二个节点里填写负向提示词，也就是“希望尽量避免什么”：

```text
text, watermark
```

这里是希望尽量避免文字和水印。**负向提示词不是橡皮擦**：写了不代表这些内容一定完全消失。

现在接线：用鼠标左键从 `Load Checkpoint` 的 **CLIP 输出圆点**拖到一个文本节点的 **clip 输入圆点**，然后松开。再从同一个 CLIP 输出圆点拖一次，接到另一个文本节点的 clip 输入。也就是说，一个输出可以分别连接到两个节点。

可以把这一步理解为：先把工具交给两位负责处理文字的工位。正向和负向虽然都叫文本编码节点，但因为写的内容不同、后续接的位置不同，发挥的作用也不同。

### 第四步：KSampler —— 让生成过程真正动起来

添加 **KSampler**。

**一句话理解：KSampler 把模型、文字要求和空白数据放在一起，逐步得到用于生成图像的结果。**

如果把前面的工作看成准备材料，KSampler 就像开始制作的工位。先把下面几条线接好：

1. `Load Checkpoint` 的 **MODEL** → KSampler 的 **model**。
2. 写正向提示词的节点的 **CONDITIONING** → KSampler 的 **positive**。
3. 写负向提示词的节点的 **CONDITIONING** → KSampler 的 **negative**。
4. `Empty Latent Image` 的 **LATENT** → KSampler 的 **latent_image**。

注意第二、三条：两个文本节点的输出类型一样，正负接反不一定报错，所以要看清 `positive` 和 `negative`，不要只看线的颜色。

接着设置参数。别被英文吓到，每个参数这次只要理解它在调整什么：

- **seed：`156680208700286`**。可以把它想成这次生成所用的一份随机起点编号。其他条件不变时，换一个 seed，画面构图通常也会跟着变化。
- **seed 控制：`fixed`**。让这次实验尽量保持同一个随机起点，方便稍后对比。不同版本显示位置可能略有差异；确认运行时使用的是上面的 seed。
- **steps：`20`**。生成会经过一系列步骤；步数改变可能影响细节和耗时，但不是越多越一定好。
- **cfg：`8.0`**。可以先理解为“生成时参考提示词的力度”。太低可能不够贴合，太高也可能让画面不自然；这节课先用示例值。
- **sampler_name：`euler`**。它决定采样时采用哪种方法，先选示例使用的 `euler`，不用现在记住所有选项。
- **scheduler：`normal`**。它安排生成过程中各步骤的变化节奏。本课先固定为 `normal`。
- **denoise：`1.0`**。可以先把它理解为这次生成要走多完整的变化过程。本课从空白数据开始，使用示例的 `1.0`；后面学修改已有图片时，我们再深入讨论。

这里的数值是**为了跑通并对照本课示例**，不是所有模型都通用的最佳答案。

### 第五步：VAE Decode —— 把结果转换成能看的图

添加 **VAE Decode**。

**一句话理解：它把生成过程中的潜空间数据转换成普通图像。**

可以把前一步的结果暂时想成一份还需要冲洗的底片：信息已经有了，但我们还需要把它转换成方便查看的图片。这个比喻不完全等同于真实的计算过程，记住“转换成图像”就够了。

接好两条线：

1. KSampler 的 **LATENT** → VAE Decode 的 **samples**。
2. `Load Checkpoint` 的 **VAE** → VAE Decode 的 **vae**。

### 第六步：Save Image —— 把图保存下来

添加 **Save Image**。

从 VAE Decode 的 **IMAGE** 输出，连到 Save Image 的 **images** 输入。`filename_prefix` 可以先保持 `ComfyUI`，它是保存文件名的前缀。

**一句话理解：前面的节点负责把图做出来，Save Image 负责把结果存下来。** 默认情况下，图片通常保存在 ComfyUI 的 `output` 文件夹；如果你自己改过输出路径，以实际配置为准。

到这里，流水线就搭好了。别急着点运行，先从头检查一下：**模型、空白数据、两个文本节点，都接到了 KSampler；KSampler 接到解码；解码接到保存。**

## 三、运行：看看我们能得到什么

确认模型、提示词和参数填好后，点击界面中的 **Queue / Run / 运行**。不同版本按钮文字可能不同。首次运行需要加载模型，等待一会儿是正常的。

运行完成后，在 **Save Image** 节点查看结果，并到输出目录找到保存的图片。

我们使用了示例的模型名称、提示词、尺寸和采样参数，也固定了 seed，所以是在**尝试接近开头的参考图**。但不同设备、模型文件、ComfyUI 和相关软件版本可能带来差异，不能保证每台机器都得到像素完全相同的图片。先看整体是否符合提示词：有没有玻璃瓶、紫色星河和自然场景，再观察细节。

如果结果不理想，先别急着改一大堆参数，按顺序检查：

- **模型选不到**：检查文件位置、下载是否完整，刷新或重启 ComfyUI。
- **提示输入缺失或连不上**：对照节点端口名称检查连线；颜色可以辅助，但是否兼容还要看端口类型。
- **画面明显不符合要求**：确认正向和负向没有接反，模型、提示词、尺寸和参数与上面一致。
- **显存不足**：先确认尺寸是 512 × 512、`batch_size` 是 1，关闭其他占用显存的程序后再试。

如果你暂时卡在搭建，也可以下载[原始示例 PNG](/img/external/raw-githubusercontent-com/basic/text-to-image-workflow.png)，把原图拖入 ComfyUI 画布，作为连线参考。原工作流使用的是 `randomize`：如果要按本课继续做对照实验，记得将控制方式改为 `fixed`，再确认 seed 是 `156680208700286`。**这张原始文件包含工作流信息，但不包含模型文件。** 截图、转发或重新编码后的图片可能丢失这些信息。

## 四、改一处，再看一眼：参数为什么重要

第一张图出来后，先保存它，作为我们的**基线**。接下来做对照实验时，记住一个方法：**一次只改一件事，其他条件保持不变。** 否则图片变了，我们很难知道是哪一个改动造成的。

### 实验一：换一个 seed，看看随机起点

先保持提示词、模型、尺寸和其他采样参数不变，把 seed 从 `156680208700286` 改为 `156680208700287`，控制方式仍然选 `fixed`，再运行一次。

比较两张图：主体可能仍然是玻璃瓶，但瓶子的形状、位置或背景构图可能发生变化。换 seed 不等于换模型，也不等于修改提示词；它改变的是这次生成的随机起点。

看完后，把 seed 改回 `156680208700286`，为下一个实验恢复基线。

### 实验二：只改提示词，看看文字如何影响画面

其他条件都保持基线不变，在正向提示词里，把 `purple galaxy bottle` 改成 `blue galaxy bottle`，然后再运行一次。

这次我们只把“紫色星河瓶”改成了“蓝色星河瓶”。观察颜色和画面是否发生变化。模型不一定会完全听从每个词，颜色也可能受到其他词和生成过程影响；如果变化不明显，同样是一个值得记录的结果。

做完后，你可以把提示词改回原文，再试着改变你感兴趣的另一个词。每次只改一处，你会更快建立“我改了什么，图片可能怎样变化”的直觉。

## 五、最后总结一下

今天我们从空白画布搭出了一条文生图工作流：

- **Load Checkpoint** 加载模型；
- **Empty Latent Image** 准备指定尺寸的空白数据；
- 两个 **CLIP Text Encode** 分别处理正向和负向要求；
- **KSampler** 根据模型、条件和参数进行生成；
- **VAE Decode** 把结果转换成图像；
- **Save Image** 把图保存下来。

如果现在还记不住所有英文名称，完全没关系。比背名字更重要的是，你已经知道怎样看一条工作流：**每个节点负责什么，它从哪里接收东西，又把结果交给谁。**

你可以试着不看教程，重新搭一次；如果卡住，再回来对照相应的步骤。能自己发现问题、找到一条接错的线，就是很好的进步。
